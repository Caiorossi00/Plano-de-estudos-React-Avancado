O método componentDidUpdate(prevProps, prevState) é um dos principais mecanismos de sincronização dos componentes de classe do React. Enquanto o componentDidMount é executado apenas uma vez após a montagem inicial do componente, o componentDidUpdate é chamado sempre que ocorre uma atualização. Essa atualização pode ser provocada por mudanças nas propriedades recebidas (props), alterações no estado interno (state) ou por uma nova renderização causada pelo componente pai. Seu objetivo não é alterar a interface diretamente, mas permitir que o componente execute efeitos colaterais em resposta a mudanças específicas.
Para compreender esse método, é importante lembrar que o react trabalha seguindo um ciclo de renderização. Sempre que algum dado utilizado pelo componente muda, o react executa uma nova renderização, compara a nova árvore virtual com a anterior através do reconcilier e, após aplicar as altierações necessárias no DOM durante a commit phase, chama o componentDidUpdate. Isso significa que, quando esse método é executado, a interface já representa o estado mais recente da aplicação. 
Uma característica importante desse lifecycle é que ele recebe dois parâmetros: prevProps e prevState. Eles representam, respectivamente, as propriedades e o estado que o componente possuía antes da atualização acontecer. Ao mesmo tempo, o componente continua tendo acesso a this.props e this.state, que agora representam os valores atuais. Dessa forma, o react fornece simultaneamente duas versões dos mesmos dados: a anterior e a atual. Essa comparação é a base de funcionamento do método.
O principal motivo para essa comparação é que o componentDidUpdate é executado após todas as atualizações do componente. Se o react não fornecesse os valores anteriores, o desenvolvedor não teria uma maneira simples de identificar qual informação realmente mudou. Imagine um componente que recebe um identificador de usuário através das props e precisa buscar novamente os dados sempre que esse identificador for alterado. Não faria sentido executar uma nova requisição após qualquer renderização, pois isso geraria chamadas desnecessárias para a API. Em vez disso, compara-se o valor antigo com o novo e apenas quando existe diferença o efeito é executado.
Essa lógica pode ser representada da seguinte forma:
componentDidUpdate(prevProps) {
	if (prevProps.userId !== this.props.userId) {
		this.buscarUsuario();
	}
}

Observe que a sincronização não acontece porque o componente foi atualizado, mas porque uma dependência específica mudou. Essa é a ideia central do método. O desenvolvedor define quais informações são relevantes para determinado efeito e compara seus valores anteriores com os atuais antes de tomar qualquer ação.
Esse comportamento possui uma relação direta com o useEffect utilizado nos componentes funcionais. 
Quando escrevemos um hook como: 
useEffect(() => {
	buscarUsuario();
}, [userId]);

O react passa a realizar automaticamente a comparação entre o valor anterior e o valor atual de userId. Nas classes, essa responsabilidade pertence ao próprio desenvolvedor através do prevProps e prevState. Em ambos os casos, o objetivo é exatamente o mesmo: executar um efeito somente quando suas dependências forem modificadas. 
Essa comparação manual também é fundamental para evitar um dos problemas mais comuns envolvendo esse lifecycle: os loops infinitos de renderização. Como o método é executado após toda atualizaão, chamar setState() incondicionalmente dentro dele faz com que uma nova atualização seja disparada, que por sua vez executa novamente o componentDidUpdate, criando um ciclo que nunca termina. Por esse motivo, praticamente toda utilização correta desse método envolve alguma condição baseada em prevProps ou prevState.
Esse padrão aparece constantemente em aplicações react legadas. Em projetos que utilizam redux, por exemplo, é comum que uma atualização na store faça com que o componente receba novas props através do connect. O componentDidUpdate detecta essa mudança e executa alguma sincronização adicional, como preencher um formulário, buscar informações complementares ou atualizar componentes externos. Em aplicações que utilizam redux-form, também é frequente utilizar esse lifecycle para iniciar novos campos quando determinados dados são carregados de forma assíncrona. 
Apesar de o react moderno incentivar o uso de hooks, compreender o funcionamento do componentDidUpdate continua sendo importante porque ele representa a origem conceitual da sincronização baseada em dependências. Os hooks não eliminaram essa necessidade, apenas mudaram a forma como ela é expressa. Enquanto nas classes o desenvolvedor compara mannualmente os valores anteriores com os atuais, nos componentes funcionais essa comparação passou a ser declarada através do array de dependências do useEffect. A filosofia, entretanto, permanece exatamente a mesma: efeitos colaterias não devem ser executados após toda renderização, mas apenas quando os dados dos quais eles dependem realmente sofrem alterações.
