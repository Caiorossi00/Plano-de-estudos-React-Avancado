Nos componentes de classe do react, existem duas formas comuns de declarar métodos: utilizando a sintaxe tradicional de classes ou através de arrow functions atribuídas como propriedades da classe. Embora ambas permitam definir comportamentos para o componente, existe uma diferença fundamental entre elas relacionada ao funcionamento do this. Compreender essa diferença exige entender que, no javascript, métodos e funções não tratam o contexto de execução da mesma maneira.

Um método tradicional é definido diretamente no corpo da classe e faz parte do seu protótipo. Isso significa que todas as instâncias daquele componente compartilham a mesma implementação do método, tornando essa abordagem eficiente do ponto de vista da memória. Entretanto, esse tipo de método não possui um this fixo. Seu contexto é determinado no momento em que ele é chamado. Se for executado através da própria instância, o this apontará corretamente para o componente. Porém, se esse método for passado como callback para outra função, ele poderá perder essa associação e deixar de saber qual instância deve representar.

Foi justamente esse comportamento que gerou muitos problemas em aplicações react baseadas em classes. Era comum definir um método responsável por tratar um clique em um botão e, ao passá-lo para um evento perceber que this.setState() ou this.props deixavam de funcionar corretamente. O problema não estava no react, mas na forma como o javascript determina o valor de this para funções tradicionais.

As arrow functions surgem com um comportamento diferente. Em vez de definirem seu próprio contexto de execução, elas capturam o contexto léxico do ambiente onde foram criadas. Quando uma arrow function é declarada como propriedade da classe, ela passa a utilizar automaticamente o this da instância que está sendo criada. Isso significa que, independentemente de onde essa função seja executada posteriorimente, seu this continuará apontando para o componente correto.

Na prática, isso elimina a necessidade de realizar o binding manual dos métodos dentro do constructor, prática que era extremamente comum no react clássico. Isso significa que, independentemente de onde essa função seja executada posteriormente, seu this continuará apontando para o componente correto.

Apesar dessa vantagem, existe uma diferença estrutural importante entre essas duas abordagens. Enquanto métodos tradicionais pertencem ao protótipo da classe e são compartilhados por todas as instâncias, uma arrow function declarada como propriedade é criada individualmente para cada componente instanciado. Isso significa que cada instância possui sua própria cópia daquela função. Em aplicações comuns essa diferença de memória costuma ser irrelevante, mas ela explica por que métodos tradicionais continuam sendo a forma padrão de declarar comportamentos em javascript orientados a objetos.

Durante muitos anos, desenvolvedores react precisaram escolher entre essas duas abordagens. Utilizar métodos tradicionais significava escrever menos funções por instância, mas exigia lembrar de fazer o bind corretamente. Utilizar arrow functions simplificava o código e evitava problemas relacionados ao this, ao custo de criar uma nova função para cada componente. Com o tempo, a simplicidade proporcionada pelas arrow functions fez com que elas se tornassem o padrão predominante em aplicações react baseadas em classes.

Hoje, essa discussão aparece com menos frequência porque os componentes funcionais eliminaram completamente a necessidade de trabalhar com this. Ainda assim, compreender a diferença entre métodos tradicionais e arrow functions continua sendo essencial para entender bases de código legadas. Grande parte das aplicações desenvolvidas antes da introdução dos hooks utiliza um desses dois padrões, e reconhecer como cada um lida com contexto de execução permite compreender por que determinados componentes utilizam bind, enquanto outros funcionam corretamente apenas com arrow functions. Mais do que uma diferença de sintaxe, trata-se de duas formas distintas de controlar como o javascript associa funções à instância de um objeto.
